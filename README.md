# 补货规则回放系统

用同一段历史需求，对比两种补货策略在**缺货、库存占用、临期报废**上的表现：

- `rop`：库存低于补货点时补到目标量
- `cycle`：每三天评审一次，补到目标量

技术栈：Python + FastAPI + SQLite（后端/回放引擎）、React + Vite + ECharts（前端）。

## 快速启动

```bash
./run.sh
# 后端 http://127.0.0.1:8000 ，前端 http://localhost:5173
```

手动启动：

```bash
python3 -m venv .venv && .venv/bin/pip install -r backend/requirements.txt
.venv/bin/python -m uvicorn app.main:app --app-dir backend --port 8000
cd frontend && npm install && npm run dev
```

验证：

```bash
.venv/bin/python -I backend/verify.py      # 引擎不变量（守恒/负库存/FEFO/逐批对上）
.venv/bin/python -I backend/e2e_test.py    # HTTP 端到端（需先启动后端）
```

## 业务规则（引擎实现要点，见 `backend/app/engine.py`）

按天推进，每日顺序固定：

1. **中央仓收货**：中央仓到货批次入库
2. **中央仓剔除**：当天已到期批次报废
3. **门店收货**：在途批次按「发出日 + 配送天数」到货，**保留原有效期与单位成本**
4. **门店剔除**：当天已到期批次报废，记临期报废成本
5. **满足需求**：**FEFO 先到期先出**扣减；库存不足记损失需求，**不允许负库存**
6. **日终补货**：只能看到当日及以前的信息

补货量计算：

```
raw = 目标量 - 现有库存 - 在途量
requested = ceil(raw / 整箱规格) × 整箱规格        # raw <= 0 不下单
```

中央仓有限，多门店同日抢同一商品时按 **(门店优先级, 门店编号)** 排序分配，
中央仓同样按 FEFO 出批；**未分到的数量保留为缺口，不计入在途、不当成已发货**。

两种策略从同一初始状态各自深拷贝独立运行，库存互不串用。

## 场景数据（`backend/app/seed.py`）

- 3 家门店（优先级 1/2/3，配送天数 1/2/3 天）
- 4 种商品：鲜牛奶（6 天短保）、常温酸奶（21 天）、短保三明治（3 天）、瓶装水（60 天）
- 14 天逐日真实需求：工作日/周末规律 + 3 个促销尖峰
- 门店与中央仓初始批次、中央仓到货计划，批次均带有效期与单位成本

短保三明治会自然出现「缺货与报废并存」，瓶装水会出现多门店抢货与中央仓缺口，
便于观察两种策略的取舍。

## 页面

- **逐日回放**：日期推进；门店/商品筛选；当日库存、在途、需求、损失、报废 KPI；
  库存金额与损失/报废走势图；门店×商品明细表；中央仓库存；当日事件时间线
  （收货→剔除→需求→补货的顺序与批次号）。点击任一补货单弹出**计算依据**：
  决策时现有/在途、目标量、裸需求、整箱取整过程、逐批分配与到货日。
- **策略对比**：需求满足率、平均库存金额、门店报废成本三大指标对比，
  逐日满足率/库存金额/损失图，按门店与按商品明细。
- **批次对账**：按商品全局守恒（供应 = 期末库存 + 售出 + 报废）、
  中央仓→门店逐批发出量与落地量核对、全部批次台账。
- **输入数据**：商品、门店策略参数、初始批次、中央仓到货、逐日需求。

## 数据表

配置表：`products / stores / policies / initial_batches / central_arrivals / demand`
运行表：`runs / snapshots / central_snapshots / orders / order_allocations / events / reconciliation`

重新回放只清空运行表，输入数据保持不变。

## 已验证的不变量

- 任意时点无负库存（批次余量、台账结束量、快照均非负）
- 每格 需求 = 销量 + 损失
- 每单 实发 + 缺口 = 申请，缺口不发货、不入在途
- FEFO 扣减顺序按有效期升序
- 发出批次保留原有效期与单位成本，到货日 = 发出日 + 配送天数
- 中央仓每个批次发出量 = 门店/在途落地量（逐批对上）
- 按商品全局数量守恒，全部批次台账平衡
